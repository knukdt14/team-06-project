# [검색 이관] 다중 검색기 앙상블(RRF) + 페이지 중복제거 제안

- **From:** 이수민 (문서처리) → **To:** 이희영 (검색)
- **날짜:** 2026-07-27

## 배경
문서처리 개선 실험(chunk / overlap / 머리말 제거 / 표 전처리 / section 청킹) 중 발견한 것:
**방법마다 잘 찾는 문항이 서로 다르다.** 하나만 튜닝하는 것보다 **여러 검색 결과를 합치면(앙상블)** 훨씬 많은 문항을 커버할 수 있어 보임. 검색 알고리즘은 희영님 담당이라 근거 데이터와 함께 이관.

## 데이터 — 방법별 성공 문항 (검색 Hit@3, chunk500·overlap100·top_k3)
| 방법 | 성공 문항 | Hit@3 |
|---|---|---|
| PyPDF chunk500 (현재 채택) | Q1, Q2, Q5, Q6, Q9, Q11 | 0.462 |
| chunk300 | Q3, Q8, Q10 | 0.385 |
| Markdown 표 (pymupdf4llm) | Q2, Q5, Q6, Q7, Q9, Q12, Q13 | **0.538** |
| section 청킹 | Q4, Q8, Q13 (신규) | 0.385 |

→ 성공 문항을 **합치면 거의 전 문항**. 단일 방법으로는 다 못 잡음.

## 제안 (우선순위)
1. **페이지 단위 중복제거(dedup) 먼저** — 같은 페이지 청크가 top-3를 독점하는 문제
   (예: Q11 → `[181, 181, 181]`). `fetch_k=10~20`으로 넉넉히 뽑고 **서로 다른 페이지 3개**만 남기기.
2. **PyPDF + Markdown 이중 검색 → RRF(순위 융합)** — 스토어마다 점수 척도가 달라
   점수를 직접 더하지 말고 **순위**로 융합.
3. (추가) chunk300 검색 → Q3·Q8·Q10 보완.

**첫 실험 추천:** PyPDF chunk500 + Markdown chunk500 → RRF → 페이지 dedup → Hit@3 재측정.

## 🎯 Q10 정밀 처방 (진단 완료 — 유일한 미해결 문항)

- **증상:** 새 채점 기준에서 **Q10(표준세액공제)만 실패.** 정답 188쪽이 유사도 순위 **33위**, 8쪽 127위.
- **원인:** 질문("특별공제를 아무것도 신청 안 하면?")에 핵심 제도명 **"표준세액공제"가 없어** 임베딩이 답 페이지를 못 이음. **top_k(→10)·MMR·hybrid 모두 해결 실패**(검증됨).
- **처방 (우선순위):**
  1. **query rewrite (자동/일반)** ⭐ — 원 질문 + 확장 질문(핵심 제도명·키워드 보강)을 **둘 다 검색 → RRF로 합침.** Q10 해결 최유력.
     - ⚠️ **주의:** 특정 문항의 답을 손으로 넣으면 **과적합.** `LLM 재작성` 등 **일반 규칙**으로 할 것.
  2. **페이지 단위 중복제거(dedup)** — 같은 페이지가 top-3 독점 방지.
  3. **hybrid 재구성** — 현재 hybrid는 top-k 제한·가중치 불완전 (**점수 부풀림 버그** 확인됨). 고친 뒤 BM25+벡터 RRF.
  4. **평가 질문 확대** — Q10류 조건형 질문 추가해 **일반화 검증** (팀장).
- **추천 다음 실험:** `원 질문 검색 + 일반 확장 질문 검색 → RRF → 페이지 dedup → top-3 채점`
