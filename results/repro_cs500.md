## 1. 무엇을

현재 채택 설정(chunk 500/100, ko-sroberta, Chroma, similarity, top_k=3, Gemini, basic)을
**변경 없이 3회** 실행하고 지표 변동폭을 측정했다.

- 1회차: 기존 `cs500` 실행(이수민)을 새 채점기로 재채점한 값 (`detail_cs500_scored.csv`)
- 2·3회차: `cs500_r2`, `cs500_r3` 신규 실행 (유료 API 키 전환 후)

## 3. 의미 (이후 실험의 판단 기준)

1. **BERTScore 노이즈는 ±0.005 수준.** → 앞으로 **±0.01 이내 차이는 "개선 아님"**으로 취급한다.
2. **수민의 chunk_size 개선(0.696→0.742, +0.046)은 노이즈의 약 9배** → 확실한 개선으로 확정.
3. **numeric_acc는 ±0.026씩 흔들림** — 13문항뿐이라 1문항 차이가 곧 ±0.077(숫자 부분점수 기준 ±0.026).
   → **평가셋 확장(§3)이 필요하다는 정량적 근거.** 문항이 60개면 같은 1문항 노이즈가 ±0.017로 줄어든다.
4. **검색 지표(Hit@3, E3:8)는 3회 모두 동일** — retriever는 결정적이므로 검색 실험은 반복 불필요,
   LLM이 끼는 평가만 반복이 의미 있다.
5. 변동은 생성 단계에서만 발생(WR·E6 소폭 변동) — LLM temperature=0이어도 API 응답이 완전히
   동일하지는 않음을 확인.
